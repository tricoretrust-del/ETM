# ETM 보관 구조 v0 (최소 구조)

작성 2026-11-23. 근거 자료: Google Sheet 'GEO.통합관리_Test'(2.비용 4,969줄, 3.출고 3,813줄, 4.생산매입 1,011줄)와 사용자 답변.

원칙
- 기록 → 처리 → 보관 → 조회의 체인을 흔들지 않는다.
- 가장 단순한 구조에서 출발하고, 측정된 개선이 있을 때만 복잡성을 더한다.
- 모든 데이터는 세 가지 틀로만 보관한다: **돈의 흐름**(채권·채무), **가치의 흐름**(재료·완제품·서비스), **미결/완결**.
- 한 번의 입력(사건 1건)이 가치 이동과 돈을 함께 만든다. 재고, 원가, 월 합계, 일일보고는 보관하지 않고 조회로 계산한다.
- 인사·급여(6.근태, 8.급여대장, 10.계좌정보)는 v0 범위에서 제외한다.

## 1. 표 (보관 대상은 이것뿐)

### 1-1. 기준정보

| 표 | 칸 | 비고 |
|---|---|---|
| 품목 | 코드, 이름, 유형, 기본 단위, 단위 환산, 재고 관리 여부, 소유(자사/타사), 비용 성격, 표준 단가(+확인 시점), **별칭** | 코드는 SKU 탭 체계(`유형.종류.규격.컬러`)를 따른다 |
| 배합 | 배합 코드(`G.MX.11` 등), 원자재 품목, 1 MIX당 KG | 작업일보 RCP 탭 그대로 |
| 상대 | 이름, 역할(청구처 / 수요처 / 공급처 / 운송사 / 임대사), 별칭 | 한 표에 두고 역할로 구분한다 |
| 납품현장 | 주소, 차수(1차·2차…), **수요처 1곳, 청구처 1곳** | 납품현장 하나는 수요처 하나·청구처 하나에만 속한다 |

- **유형**: P(생산 제품), C(상품), S(청구 용역), MAT(원자재), CHG(용역·임대·수수료). 그 밖의 유형은 측정 후 추가한다.
- **단위 환산 예**: 모래 1 M3 = ? TON, 규사 1 BAG ≈ 1.6 TON.
- **비용 성격**: 고정 / 변동 / 운영.
- **별칭**: 같은 품목이 두 통합 문서와 전표에서 다른 이름으로 불린다(예: `CSTN_석분` = 비용 탭 '석분' = `MAT.AGG.STD`). 품목 하나에 별칭 목록을 둬서 하나로 묶는다. 별도 코드 체계를 새로 만들지 않는다.
- **기본 단위**: 원자재는 KG(배합이 KG 단위). TON = 1,000 KG, 석분·모래 1 M3 = 1,450 KG(작업일보 MAT 메모), 규사 1 BAG ≈ 1,600 KG(통합관리 메모). 환산값은 품목에 둔다.
- **표준 단가**(작업일보 REF·MAT)는 일일 손익용 참고값이다. 실제 원가는 매입 단가로 계산한다(§3).
- **청구처 – 수요처 – 납품현장** (시트의 거래처 – 업체명 – 현장주소)
  - 청구처(Bill-to): 우리가 청구하고 돈을 받는 상대. **우리 채권은 청구처에 대해서만 있다.**
  - 수요처(End customer): 청구처에 대금을 내는 건설회사. 청구처의 채권 상대이며, 우리에게는 참고 정보다.
  - 납품현장(Ship-to): 실제 납품지. 수요처는 보통 여러 현장을 운영한다.
- **납품현장 하나에는 수요처 하나·청구처 하나만 있다.** 다른 청구처나 수요처가 끼면 차수(1차·2차)로 나눈 별도 납품현장으로 등록한다. 월 결재 채권이 납품현장 단위로 맞아야 하기 때문이다.
- 한 수요처가 현장에 따라 다른 청구처를 통하는 것은 정상이다(예: 금성백조 → 반석건업 / 지오블록).
- 시트 데이터 중 한 현장에 수요처가 여럿인 11곳, 송장 1건에 청구처·수요처·현장이 섞인 109건은 이관 시험에서 **차수 분리 또는 오기 정정 대상**으로 따로 보여 준다.

## 2. 사건 종류별로 생기는 것

| 사건 | 가치 이동 | 돈 |
|---|---|---|
| 매입 (원자재·상품) | 공급처 → 공장 | 채무 (공급처), 미결 |
| 비용 (운송·임대·수리·소모품 등) | 없음. 재고 관리 품목이면 → 공장 | 채무, 미결 |
| 생산 (일일보고 1일 = 1건) | 생산 → 공장 (제품, M2). **같은 사건에서** 원자재 공장 → 생산 소비가 자동으로 생긴다: MIX 수 × 배합 KG, 안료 KG, 팔레트 EA | **없음** |
| 사용 (보정만) | 공장 → 생산 소비 | 없음. 배합으로 계산되지 않는 사용·손실을 직접 기록할 때만 |
| 출하 | 공장 → 납품현장 (제품·상품·KPP 팔레트). KPP 팔레트는 소유자 KPP 그대로 | 채권 (납품현장의 청구처), 미결. 운반비가 있으면 채무 (운송사) |

## 3. '제외(통계)' 문제에 대한 제안

**지금 시트가 겪는 문제**
- 원자재 매입(채무)과 그날그날 쓴 원자재(변동비)를 한 탭에 둘 다 '비용'으로 적었다.
- 그래서 매입 쪽을 '제외(통계)'로 표시해 이중 계산을 막았다.
- 한 표가 자금 관점(얼마를 갚아야 하나)과 원가 관점(얼마를 써서 만들었나)을 동시에 맡아서 생긴 문제다.

**제안: 두 관점을 다른 흐름에 둔다**
1. **매입은 돈에만 남는다.** 원자재 매입 = 가치 이동(공급처 → 공장) + 채무. 돈은 여기서 한 번만 기록된다.
2. **사용은 가치에만 남는다.** 사용 = 가치 이동(공장 → 생산 소비)만 기록하고, 금액은 저장하지 않는다.
3. **원가(변동비)는 조회로 계산한다.** 사용량 × 그 기간 매입 단가의 가중평균. 저장된 돈은 하나라서 이중 계산이 생길 수 없다. '제외' 표시도 필요 없다.
4. **사용량은 한 번의 입력에서 나온다.**
   - 작업일보에 이미 있는 방식을 그대로 쓴다.
   - 일일보고의 MIX 수(`G.MX.xx`) × 배합 KG(RCP)에 안료 KG와 팔레트 EA를 더하면 그날의 원자재 사용이다.
   - 생산 사건 1건이 제품 생산과 원자재 사용을 함께 만든다. 사용을 따로 입력하지 않는다.
   - 일일보고의 표준 단가 손익(NET MARGIN)은 그대로 조회로 두고, 월 원가는 실제 매입 단가로 계산한다.
   - 제품별 원가 배분(하루에 여러 제품을 생산할 때)은 조회 규칙이다. 보관 구조와 무관하므로 v0에서는 정하지 않는다.

## 6. 다음 단계 (측정)

1. **이관 시험**: 테스트 시트 데이터를 위 구조에 넣는다. 들어가지 못하는 줄 수를 유형별로 센다(품목 불명, 단위 불일치, 상대 없음, 송장 내 거래처 혼재 109건 등). 이것이 기준선이다.
2. **조회 재현**: 원자재 재고, 보유재고량, 월별 합계를 계산해 시트 숫자와 비교한다. 차이마다 시트 오류인지 구조 오류인지 판정한다.
3. 이 두 결과로 구조를 확정한 뒤에 기록·처리(직접입력 / DEX 확인 화면)를 만든다.
